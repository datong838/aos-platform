# Full source and sampled backend callback closure findings

Official PostgreSQL16.14 archive SHA256 was verified before parsing 2448 regular C/header files. All literal callback registration references were inventoried. Outside the registration API definitions, three upstream modules register Xact/SubXact callbacks: PL/pgSQL, sepgsql, postgres_fdw. PL/pgSQL and sepgsql callback bodies do not act on PRE_COMMIT; postgres_fdw can issue remote COMMIT during PRE_COMMIT. These are source-level facts, not a claim that every installed binary is reproducibly built from this archive.

One fresh exact isolated PG16.14 backend was observed under SERIALIZABLE READ ONLY. Pure no-op PL/pgSQL, empty pgcrypto digest, invalid empty ed25519 verification and Owner-only native pending observation loaded four exact library paths. The executable module map contains26 files; all file hashes were frozen. Only plpgsql.so among these four imports callback registration APIs. The signature binary retains its original SHA. Existing test-only ordering/postdrain libraries present in the catalog were absent from this backend's executable map. No business Source, row or effect was created. Readonly transaction was rolled back.

This changes the next implementation: a complete native ending must bind an exact loaded module/package profile and reject unowned modules, indirect loaders or later drift; empty preload settings and catalog probin are insufficient. Merely seeing no undefined registration symbol is also insufficient because indirect lookup can register. A supported public runtime module observation plus approved immutable package/source authority is needed; do not inspect or patch PostgreSQL private callback-list memory or assert last ordering from newest registration. Within a fully proved closed profile, an older PL/pgSQL PRE_COMMIT callback being no-op is relevant evidence, but its complete binary provenance and lifecycle still need acceptance.

Full Main eight-node Receipt precreation, original Source/fourcert/current Root and all lock waits, pre/post native pending checks, final decision clock, actual durable COMMIT/independent conservative postcommit confirmation, rollback/replay/unknown retention and formal cutover remain required. No production arm/end API, ACL change, deployment, Task Delivery or first-chain completion is granted by this audit.
