# Full native package trust contract: design input, not installed authority

This refines the original complete-ending prerequisite. It is not a new acceptance denominator, a deployed schema, a test allowlist or an approved formal Root. Existing original Root/Source,8-node/fourcert/risk/physical/Receipt,current-clock,fixedpoint,actual durable COMMIT and unknown-result requirements all remain.

## Bootstrap and authority

The validator cannot attest to its own trust solely by returning its disk/memory hashes. An independently controlled installation must first establish the exact PostgreSQL/core/dependency/native-verifier package and verification primitive from a reviewed source/build/deployment chain. Retain the current controlled-signing and installation receipts and their original Owner/tenant/approval boundaries. A Provider-capacity or Model Root purpose must not be silently reused to authorize native code. Test bootstrap/public keys are isolation evidence only; formal Root issuance requires the existing formal controlled authority.

The future native Root must bind a dedicated exact purpose and domain, issuer/key/current Root revision/origin/withdrawal epoch/validity interval, original deployment/installation identity, architecture/ABI/PG version and cluster, exact raw source/build/profile hashes and lifecycle policy. Verify signature over exact bounded bytes and current authority before consumption. Missing or withdrawn purpose/issuer/origin/window/bootstrap rejects. No caller-selected public key, supplied path/hash allowlist, optional validator, version-only trust or generic signed blob is accepted. Storage/reader/issuer ownership and ACL must be independently audited; no role or API is created by this design document.

## Complete material and profile

Bind every reviewed source/archive and patch, build recipe/configure flags/compiler/SDK/package lock, final image and actual module bytes to the controlling build evidence. APK ownership/checksums and image digests are intermediate facts, not signatures or source-to-binary proof. Include the five observed unowned components and all27 sampled dependencies; then measure the actual complete Main validator profile. Do not make that sample the full allowlist. Record data-only ELF and virtual vDSO policy explicitly, all executable mappings including anonymous/JIT or unsupported ones, file-backed readable segments and exact relocation/writable-state policy. Unsupported or unowned execution material rejects until explicitly reviewed by the same trusted contract.

## Lifetime and fixed validation

Require code/profile/lifecycle that the backend identity cannot rewrite, replace or loosen. Bind files, all containing directory/mount protections, actual identity/capabilities and exact descriptor/kernel mappings. Backend-owned chmod-only protection and writable temporary artifacts fail this requirement. The Root must specify the permitted dynamic initialization and fixed-validator reachable behavior, including indirect loaders, hooks, callbacks, planner effects, functions/operators/casts and configuration. Unreviewed LOAD/JIT/module/hook/authority drift before or after arm rejects; observation snapshots alone do not prove that nothing changes after the check. Do not inspect or patch private callback-list memory, infer newest callback is last or remove guards to achieve a pass.

## Whole-protocol acceptance

The test must use the actual legitimate Main precreated Receipt and full dependencies in one caller: all8 nodes,4 certificates, original Source and complete old/new parent risks and physical totals, engine event/deferred/RI drain with allowed fixed validation, current roots after waits, final database clock, native actual COMMIT/deadline/rollback/replay and independent conservative unknown/postcommit confirmation. Negatives include unsigned/wrong-purpose/withdrawn/profile/source/build/lifecycle mismatches, backend-writable artifact, late indirect loader/unowned executable material, deferred late writer and all original tenant/Owner/deadline/unknown gates. A fixture-signed Root or package-only test cannot produce full Task Delivery or business permission.
