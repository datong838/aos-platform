## 1. 复盘结论转成执行约束

1. 工程量确实大，但不能用任务量掩盖视觉缺失、按钮失效和业务链未闭合。
2. 历史 96/96、Workshop 44/81、AIP 132 项完成登记都不是本轮独立实测通过率。先核对对应实现与调用链，复用有效成果，只修缺口，不从头重写。
3. 从按层堆积代码改为按业务场景纵向闭合：页面入口、接口、数据、运行、产物与回读一起验收。
4. 浏览器验收前置到每个业务切片，不能等到最终波再发现漏菜单、空按钮、不可读对象和布局错误。
5. 租户、安全、真实外部副作用、迁移及发布门保留；减少的是重复查账、重复记录和不必要的全量测试，不是安全约束。
6. 暂无完整时间统计，不把效率损失武断归因于网络或模型。开始记录真实耗时，下一次复盘依据记录分析。

## 3. 推荐串行顺序与业务交付

v1.5 串行顺序：**L0 → A0-P → AR0 → AR1 → AR2 → A0-V → A1 → L1 → L2 → L3 → L4 → L5 → L7 → AR3 → L6 → A2 → A3 → L8**。AR1 细分 a/b/c/d，文件级顺序见 231-6；AR0 文档阶段不自动触发 AR1。

A0-P 是资源盘点、合同与费用授权准备，不要求尚未实现的安装运行链通过；A0-V 是底座和首链迁移完成后的实际准入复验。两者是 A0 的阶段拆分，不增加任务总数。L6 前移到连续运行之前，避免已知页面／功能缺陷带入 A3；A2/A3 如发生影响实现的修复，先重做受影响 L6/L7 与联合验收，再恢复观察。L8 仍做最终部署版本的累计检查与用户验收。

AR0～AR3 是架构纠偏行动包，详见第 18～21 节；本文 L 编号不与 230 装载方案的 L0～L6 混用。AR2 与 A1 构成首链的两道连续验收：先证明真实领域包安装后才能执行，再证明其自然触发完成业务。两道均通过才扩展；演示包通过不能代替真实电商迁移，业务链能跑也不能代替物理可插拔。

L0～L8 保留原任务映射，A0～A3 是自动运行的补充行动包，详见第 12～16 节。它们不是等量工作包，不相加形成完成百分比分母。A1 提前消费 L3、L5、L7 的最小必要切片，其后各波复用首链成果并扩展全量要求，不重复开发或重复计数。L7 前移至最终累计验收之前，避免 AIP／适配修复使已封存页面验收失效。

### L1／L2：先闭合近期未完成的四项

- L1 按已冻结 M05 方案检查合法无数据创建入口；如必须改变后端合同，先补文件级方案，不在前端伪造成功。

- L2 按同截止面核对订单源记录与页面呈现；分别解释未匹配、排除、挂接和源总量，避免以局部量冒充全量。

### L3：先做一条真实分析，再扩展完整工作区

1. 真实渠道、实体与业务可读字段；验证 API 与数据来源，不另建第二套事实权威。
2. 创建／选择 Case/Run，以一个真实只读案例贯通最小链路；AIP 编排、数据履行或运行引用缺口在这里最小修复，不留给最终集成。
3. 贯通经营画像→问题与机会→方案设计，包含暂停／继续、checkpoint、证据、评价和回读；观察、假设与有证据的结论明确区分。
4. 扩展全部标签、计划与定时、DataRequirement、人工确认、评审历史、任务建议与贡献展示。
5. 完成 BI-W10 正式试点：运行前状态、真实只读履行、完整三阶段、隔离负向、同截止 EvidencePack 和正式 Receipt。自然运行证据不能由改标签或反复重放代替。

每个切片完成即浏览器核查；最后汇总为 R6-09 与 BI-W10 相互引用的证据包，分别判断原任务是否满足，不重复算成功场景。

### L4／L5：领域功能与跨页链路

- L4 先价格五项、后客户六项串行推进；真实抓取、调价、客户发送不因为存在按钮而自动执行。
- 客户数据遵守用途、保留期、同意与脱敏要求；允许展示的汇总也不能因缺少可发送权限被误置为零。
- L5 覆盖内容、运营、达人、媒体、价格、客户六个承接页面，不能只验证一个跳转就认为全部通过。
- 复盘三段分别验证今日复盘、AI 改进建议、Wiki 候选／入库记录；技术编号只在审计详情出现，业务任务用中文表达。
- 空数据、部分数据、冲突和失败都要有真实可用的恢复入口；安全拒绝仍诚实展示，不能靠删除“未就绪”等文字掩盖功能缺口。

### L6／L7／L8：全量验收，不把抽查当封板

- L6 八页逐组件比对正式视觉稿；顶部、主体、各嵌套滚动区域和侧栏到底都检查。六数字同事浮层、十项公共能力、推荐任务、复盘三段与底部两栏列为显式验收项。
- 浏览器覆盖三视口、侧栏展开／折叠、键盘、刷新、网络失败以及空／部分／正常／冲突状态；每个适用操作记录结果，不能仅保存重复截图。
- L7 对助手、Studio、分析师、Logic、工具、成熟度、生产生命周期、评测、审批、谱系、可观测、记忆、模型目录／供应商／路由／容量／运行等实际全菜单逐一复验。助手必须能协作真实内部任务；分析师必须呈现可理解的业务结果，而不是仅列技术对象 ID。
- L7 三平台按“合同实现／样本测试／真实只读／真实执行”分别记录证据级别。当前授权不足的真实平台调用不伪造、不隐式启动；将具体授权或资源条件提交用户决定。
- L8 恢复／回滚优先用获准的隔离环境，不拿真实业务库试验。最终内部产品可验收、试点通过和允许生产发布是三种不同结论。

## 6. 固定八步执行协议

每波执行：**复习上位方案→细化当前波文件级清单→实现最小改动→专项测试→累计回归→浏览器验收→方案/代码一致性复审→证据与上下文更新→进入下一波。**

八步计数对应前八项，“进入下一波”为第 8 步闭合后的转移，不另外虚增完成步骤。

| 步骤 | 必须产出 |
|---|---|
| 1/8 | 当前方案、事实和依赖核验，明确不是依据旧记忆推断状态 |
| 2/8 | 精确文件包、任务登记和 Lease；冻结可点击验收清单 |
| 3/8 | 最小改动；优先失败测试→实现→重构，不重写已有效能力 |
| 4/8 | 新增逻辑、错误路径与权限隔离专项测试 |
| 5/8 | 受影响依赖的累计回归；共享合同或安全变化扩展测试范围 |
| 6/8 | 内置浏览器逐操作验证及真实只读／获准内部流程结果 |
| 7/8 | 方案与代码双向对照，缺陷修复后复审，不凭一次扫描通过 |
| 8/8 | EvidencePack、Delivery Receipt、安全提交、允许范围内 CAS、确定性同步与 memory validate/gate、独立 Prime 回读；注明下一个实际 Task |

进度消息格式：`Lx/Ax｜第 n/8 步｜当前业务目标｜已取得证据／当前缺口`。第 8 步注明具体下一波与首个任务；只有实际开始后才说“已进入”。A 包同样执行八步协议。当前文档维护不启动执行。

## 7. 效率优化与恢复策略

- 一个可独立验收的业务切片作为任务单位，不为每个字段重复建立完整治理链；既有必须保留的 Task/Lease/Receipt 不能擅自取消或合并。
- 专项测试随修改执行；受影响累计测试在切片／波次边界执行；L6、L8 跑全范围验收。仅当代码和依赖哈希均未变时复用历史确定性测试证据，并明确复用来源；运行健康和真实数据新鲜度必须重新核对。
- 独立 Prime Agent 只读复核“任务—改动—证据—下一步”，并按现有项目协议提交独立事实回读。它不是第二个业务代码执行者，不能自建第二份 authority；未取得回读不能声称已同步。
- 维护单一接续摘要及原任务／Receipt引用，authority仍是状态权威，不反写authority。格式按§7.4/§8直接执行；生成工具不是开码前置，不另建第二套进度系统。
- 中断后先核验版本、活跃 turn、Lease、工作树和最后一个证据闭合步骤；从首个未闭合步骤续跑，不无条件重新执行整波。
- 同一问题最多两次同路径尝试后进入根因定位，禁止重复唤醒—重复只读检查—重复相同结论而不改变诊断路径。技术缺陷在范围内直接修复；真实授权、外部资源或竞态缺口需要用户决定时精确报告，不扩大权限。
- 用户确认本计划可连续执行后，普通小任务或提交完成不结束主线；用户要求暂停、发现活跃执行冲突或需要新授权时停止对应操作并记录现场。不得用新自动化绕过暂停指令。

### 7.2 首链最小范围与禁止膨胀

首链只建设已选内部签名包的 OCI profile、所需 SDK ports、一个 Niushop 适配切片、一个微商城实体、一条分析→内容流程、文字产物及相应审批／费用／恢复机制；权限隔离、签名、持久幂等和装卸对账属于必需安全能力，不得裁掉。

首链前不提前做公开插件市场、任意语言运行器、高级无停机热升级、三平台全量业务或全部媒体模态。它们若属于已承诺功能，继续留在原 L7/AR3/A2 对应范围，不新增首链前置；第二领域／双租户／双版本的必要隔离反证测试仍保留。

新增需求只有直接影响当前链正确性、安全性、兼容性或可用产物时才进入当前切片。登记“缺口→阻止哪个验收动作→最小文件改动→测试”，普通改进放回原责任波。AR1结束后直接迁首链，不以通用底座尚可完善为由继续横向扩展。

| A2-04 达人邀约 | 从合法候选数据生成候选排序、邀约方案与跟进计划，按获准事件推进 | 内部方案与真实触达分别验收；真实发信须对象、渠道、范围批准，记录送达／失败，不把草稿算触达 |
| A2-05 多媒体 | 从真实商品或活动任务自动调用获准能力，生成文件、质检、评审并交付 | 每一种承诺可用模态都要真实生成可播放／打开文件；图像／音频／视频不能用文案生成通过替代 |
| A2-06 经营参谋 | 周期分析真实指标，完成画像、问题与机会、方案及任务建议 | 结果有来源和质量评价；无依据的相关性不写成因果结论；形成后续内部任务 |
| A2-07 价格治理 | 获准数据更新触发异常识别、策略草稿与审批 | 真实策略和证据可对账；无竞品事实不能伪造；改价获批后需校验远端结果，否则仅称监测／建议自动化 |

每场景开始前明确“内部自动完成”与“对外动作完成”的验收等级。每场景至少一次真实自然触发完整成功，并验证一次适用的人工确认／异常路径；共享底层故障测试可复用，但不能省略各页实际业务结果验收。真实事件不足时明确等待条件，不制造客户业务事件；获准测试事件仅标测试证据。

- [ ] A2 八工作台各有真实自动场景及可用业务结果；未批准外部动作单独列出，不冒充完成。

- [ ] L6 八页及 L7 AIP 全菜单完整功能、视觉、数据验收通过；真实 AdapterPack 能力与承诺范围一致。

- [ ] 用户实际操作验收；运营负责人能从 UI 启停、审批、处理异常、查看产物及用量，无需开发者改库。

## 18. 架构纠偏的最终目标与存量判断

**物理可插拔是最终必交付，不是可选优化，也不是登记安装状态或隐藏菜单。** 平台基础部署不携带电商领域可执行实现；领域包／平台适配包以独立、可校验的版本制品交付，安装后按租户绑定加载，卸载后停止并释放相应执行资源。公共内核继续提供通用安全、调度、治理和存储能力，不另造第二套权威。

安装与启用必须贯通：制品完整性与签名校验→依赖／权限／迁移预检→获准的安装事务→运行隔离单元加载→安装健康验证→配置入口可用；随后完成业务配置、权限／预算复验并获准启用，业务调度才生效。任一步失败必须有可回读状态和补偿；安装成功与业务已启用分开记录，不得暗中调用真实能力。

卸载必须贯通：阻止新调用和调度→处置在途任务与审批→排空或按策略取消→撤销绑定、路由、菜单、订阅、定时任务与运行句柄→释放进程／容器等隔离资源→记录结果。正在被其他租户或版本引用的共享制品不得删除；无引用缓存按保留策略回收。卸载不默认删除业务数据、产物、历史审计或外部平台资源。停用、卸载、数据销毁必须分开，重装须可按获准策略恢复关联。

当前审查判断基于此前读取的代码截止点 `36942b23`，开工时重新核实，不作为当前运行完成证明：

- 已有安装控制面、卸载状态转换、替换保护和相关数据库测试，应复用；不能接受“完全没有卸载实现”的笼统结论。
- 领域后端仍由平台聚合路由间接导入，前端仍有固定电商入口；包内可执行交付、装载隔离和实际卸载资源闭环不足。这是需要补齐的物理边界，不是推翻全部现有业务成果。
- 新增 runtime 合同可能改变旧 manifest 的序列化、哈希和签名；必须有兼容设计与旧包回归，不能顺手给旧包加入默认字段。
- 不能只按文件名数量、注册状态或 demo 测试判定纠偏成功；必须核查传递依赖、最终部署制品和真实电商包的生命周期。

依据为上位 20d 四层总纲、228 通用内核与领域包方案，以及本目录的 229 审查正文／附录、230 装载方案、230-L0 编码检查、230-L5 API/SDK/UI、230-L6 不变量和 230-D4-R 暂停矩阵。它们是待核对的设计输入，矛盾与过时判断须通过 AR0 明确修订，不因文件存在就视为合同已冻结。

4. **持久数据与迁移**：领域拥有数据含义，平台控制存储权限；明确共享 schema 或隔离命名空间策略、版本下限、迁移锁和真实数据库角色。租户安装记录不能代替物理 schema 隔离，卸载不能默认执行破坏性回滚。
5. **兼容与制品**：旧 manifest 哈希／签名、纯内容包 runtime 缺省、API/SDK 版本、旧任务引用、安装回读及 UI 深链接；变更与旧包兼容样本一起冻结。
6. **发布与升级**：明确本阶段安全替换、兼容窗口和回滚底线；高级在线热升级不得凭一个不存在的方案引用宣称覆盖。本文件 231 是长程计划，不是完整升级技术合同，详细合同必须另行明确落点。

文件落点规则：AR0 精确列出 `services/aos-api/aos_api/asset_registry/` 现有合同与生命周期文件、拟新增通用运行目录、平台路由／前端加载入口，以及 `bundles/` 下各目标领域包和 AdapterPack 的实际目录。文件包必须包含后端、前端资源、测试、构建与部署制品配置；不得只移动 Python 文件而遗漏静态打包的前端业务代码。
