# W5c9j｜OpenAPI 离线冷/热成本计量

方案 `m1@c2fb21fb`。一次独立短命 Python 进程，显式设置 Host=0/Cron=false/snapshot=false/migration disabled 与其它后台开关 off，导入 `aos_api.main.app`，**不进入 lifespan、不绑定端口、不请求业务路由/数据库/商城源**。90 秒 alarm 有界，完成后进程退出。导入时程序输出 dotenv 已加载日志；环境中预设的禁用开关没有在本实验中作逐项读回，因此本实验不能代替真实进程七旗标前检。已观察到若干 Pydantic field-shadow 与重复 Operation ID 警告，未打印 schema 正文/凭据。

同进程一次冷 `app.openapi()`、一次热返回：导入 6.019 秒，冷 6.241 秒，热约 0.000001 秒；顶层聚合路由 14、OpenAPI paths 2711、紧凑 JSON 5,243,651 字节，冷/热是同一对象。这个隔离结果与 W5c9i 真进程首次 5.006676 秒超时、随后热 0.044676 秒成功的量级一致，支持首次生成成本解释，但两环境不同，不能断言真进程首次生成的精确时间或唯一根因。

分类：性能/可观测性债，不是执行正确性修复授权。本波无代码修改，不预热主进程（会增加启动负担），也不改全局客户端超时。重复 Operation ID 是另一独立文档契约债，需精确定位和风险评估后另波处理；不因警告宣称所有 API 冲突。8080 业务浏览器离线，真实 A0-V 权威未变。
