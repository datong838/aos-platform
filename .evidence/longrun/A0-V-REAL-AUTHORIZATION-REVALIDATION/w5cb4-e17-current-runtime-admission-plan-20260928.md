# W5CB4 E17：当前签名目录、三身份与首链正式准入（2026-09-28）

## 上位与目标

承接 AOS 240、E16 verification，复习 231/231-2/231-3/231-9 与栖月汇产品方案。主目标不是修旧快照或把测试做绿，而是让当前 approved 安装在正式签名制品、独立运行身份、精确租户 Owner 和配置候选齐备后自然进入首条业务链。当前 Host/assignment/operation/binding 为0，八工作台不可见；不得以签名回执或 HTTP200 冒充可执行。

## 文件级清单与九步

1. 只读盘点 `.env` 中 `AOS_BUNDLE_ROOT` 的目录存在性、当前 build/signing receipt 与 Registry exact lock、当前 bundle 文件索引、OCI 固定 context、目录/runtime/Web 三个数据库 principal 及各自角色（只报告身份类别，不输出 DSN/密钥）。仅当前命名卷与库，不读商城源或旧历史堆；核对当前进程 Host 仍禁入。
2. 先确认前述权限和安装产品契约。将缺口按“可用现有权威修复 / 需正式创建身份或授权 / 与首链无关暂缓”分组，避免细节拖住主线。若所需权威缺失，本波不造假身份、不改服务开关，仍进入独立首链配置或可见性代码切片。
3. 只对可证明的当前路径做 RED 和最小修复：优先调整开发预览 profile 的**当前签名根显式选择与开机自检**，使不存在目录早期、清晰拒绝；不把默认 Host 从0改为1。预计文件为 `scripts/a0v_current_preview_http.py`、`services/aos-api/tests/extension_runtime/` 相邻启动测试；如当前脚本已有可靠保护则不重复编码，只记证据。任何 `.env` 变更先证明指向 exact 已签名根且不暴露密钥。
4. 专项/累计回归包含启动禁入、签名校验、三身份 selector、E16 Host 准入、前端运行面板。测试隔离库可自动创建清理，但不删除生产/当前权威卷、库和备份。
5. 浏览器只读验收安装、配置候选、八工作台入口与禁入文案；只有所有正式前置同时成立才考虑有界自然 Host 启动和观察，未知结果冻结不重发。不得手工 `run_definition`、重放旧12 Run、读取商城源。
6. 方案/代码一致性复审，特别核对同租户、签名 digest、独立三身份、OCI 隔离、幂等 Receipt 与消费期 Owner；不能以测试夹具授权替代正式授权。
7. verification 落盘、精确 m1 提交，AOS/Prime 上下文更新；每日用当日最新代码和同一权威卷重启 DB/API/Web 并自检，随后继续下一波。

执行节拍为复习→文件级清单→最小实现→专项→累计→浏览器→复审→证据/上下文→下一波。停止门：任何身份、签名、Owner 或外部效果未知则保持 Runtime Host/worker 禁入，转只读对账或独立首链代码，不假定许可、不重发。m1 单写者、不 push、不删除任何库/卷/备份，230 L0 挂起。
