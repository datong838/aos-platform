# AR1-c 签名安装与四源配置联合生命周期检查点

- 日期：2026-09-06
- 租户边界：专用 PostgreSQL `127.0.0.1:18432` 临时 schema；业务命名仅为隔离夹具，不是业务数据
- 外部副作用：0；Provider 调用：0；预算 receipt/hold：0；页面变更：无

## 已验证链路

签名资产安装 → 隔离 OCI 准备 → 运行验证 → 当前冻结职责计划、当前数据分类、当前预算、当前运行策略及其依赖联合准入 → 配置持久化与消费 → 启用 → 保守停用。

职责计划使用非空 W6 治理字段：`STANDARD` 画像、ProfileRecommendationRevision、确认记录、MergePolicyRevision、合并决定与对应 canonical receipt。签名生命周期已移除 `test.signed.configuration` 表与三个伪 reader。

## 失败关闭反证

- 治理确认字段漂移而内容哈希未更新时，配置写入拒绝且事务回滚。
- 配置操作已进入围栏后，职责计划 head 移动时消费拒绝且状态不前进；恢复隔离故障后可重试。
- 预算 head 移动时消费拒绝且状态不前进；恢复隔离故障后可重试。
- 配置依赖失效不阻止授权后的保守停用围栏。
- 既有权限撤销、ACK 回滚、幂等冲突、旧配置启用拒绝与零预算 receipt 断言仍通过。

## 结论与边界

当前签名隔离联合场景已使用四类正式配置 authority，不再由命名测试引用支撑。独立 Prime 复跑 22 项通过且未发现当前边界内的确定性阻断，但确认生产启动树尚无组合工厂的非测试调用点；W6 治理引用也只证明结构与职责计划哈希，未逐项读取其自身 authority。该检查点仍不是业务激活完成证明：没有真实业务任务、费用 hold、Provider、发布、共享迁移或浏览器可见效果。下一波应先闭合实际 runtime 组合入口与启动级验收，再进入持久全租户配置宿主及重启、租约与消息重投。
