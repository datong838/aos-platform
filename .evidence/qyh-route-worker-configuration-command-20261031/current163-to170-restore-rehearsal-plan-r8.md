## 3. 一致备份

1. 再次确认来源容器、卷、数据库身份、迁移头、活动连接和 prepared transaction；
2. 来源数据库只通过容器内本地 socket 访问，不读取密码；
3. 使用 `pg_dumpall --globals-only --no-role-passwords` 备份角色和全局权限；
4. 使用 PostgreSQL 16 的 custom format `pg_dump` 备份 `aos_meta_head` 全部 schema、数据、ACL、策略、触发器和注释；
5. 备份写入独立备份卷，不写工作树，不进入 Git；
6. 记录两个备份文件的 SHA-256、字节数、工具版本及来源身份；
7. 备份前后再次核对迁移头、角色目录摘要和来源 LSN；来源业务库不执行任何写入。

全局备份不保存角色密码；恢复实验不需要也不得复制正式凭据。

## 4. 独立恢复

1. 以当前来源同系列 PostgreSQL 16 镜像创建全新恢复卷和容器；
2. 恢复容器只发布本机回环 18457，不接入业务网络，不被正式 API 使用；
3. 使用临时实验管理员初始化空集群；
4. 先恢复无密码角色和全局授权，再使用 custom dump 创建并恢复 `aos_meta_head`；
5. 恢复完成后核对：数据库名、迁移头、表数量、各 schema 行数、角色属性、角色成员、ACL、RLS、策略、触发器、函数及关键不可变表摘要；
6. 来源与恢复副本的业务数据、对象目录和权限摘要必须一致；物理 system identifier、数据库 OID 和容器/卷必须不同。

任一对象或数据摘要不一致，停止在恢复阶段，不执行迁移。

## 5. 163→170 迁移

恢复副本一致后，使用提交 `6bb266200` 的代码和同一 Python 依赖执行 `alembic upgrade head`。迁移范围固定为：

1. `a0v_164`：预算策略窗口运行入口；
2. `a0v_165`：评估器风险只读策略；
3. `a0v_166`：分发配置刷新激活链，包含目标表 ACCESS EXCLUSIVE 锁；
4. `a0v_167`：模型路由评估发布读取；
5. `a0v_168`：路由评估执行命令/结果不可变日志；
6. `a0v_169`：路由评估最终化证明；
7. `a0v_170`：路由评估发布材料。

迁移前后都要记录完整对象摘要。迁移必须一次明确成功并到达唯一头 `a0v_170`；失败或结果 unknown 时不重跑，先只读核对迁移表、对象目录和日志。

1. 创建 `LOGIN NOINHERIT` 的专用角色；
2. 只让其拥有 public schema USAGE 和 `bundle_installation_command` 的 SELECT/INSERT；

该步骤只在隔离副本产生测试回执，绝不连接当前权威库。
