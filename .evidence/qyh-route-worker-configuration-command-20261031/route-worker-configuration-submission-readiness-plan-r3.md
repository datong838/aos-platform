# 后台处理配置保存就绪语义方案 r3

时间：2026-10-31（Asia/Shanghai）

## 1. 问题

当前配置预览只核对：当前客户安装、后台业务身份、受保护保存位置和身份凭据。四项通过后页面显示“后台处理配置可以确认”，但正式 API 仍有两道未开通的硬门：

1. 当前业务库没有配置回执专用身份和硬租户策略；
2. 正式只读 HTTP 外壳仍拒绝配置 POST。

因此“四项前置通过”只能证明材料齐备，不能证明配置现在可保存。继续向运营人员显示“可以确认”不符合真实业务语义。

## 2. 目标语义

配置预览新增第五项“配置保存通道”。只有同时满足以下条件才通过：

- 专用身份文件存在且可信；
- 专用数据库登录通过 r1 的最小权限和硬租户校验；
- 正式运行显式设置 `AOS_ROUTE_WORKER_CONFIGURATION_POST_ENABLED=1`；
- 只读 HTTP 外壳仅对精确路径 `/v1/ecommerce-workshop/background-processing/configure` 放行 POST。

任一条件不满足时：

- 页面状态为“条件未齐”；
- `approvalAllowed=false`；
- 显示“配置保存通道尚未开通”；
- 不读取 secret 正文、不写数据库、不写配置、不申请 token、不处理业务。

## 3. 最小实现

1. 专用连接模块增加只读 readiness probe：只读取身份文件、连接数据库并检查 catalog，始终保持只读，验证后关闭；
2. 业务入口工厂新增可注入的 readiness probe，并把显式 POST 开关纳入第五项；
3. `ReadOnlyManagementApp` 增加严格布尔构造参数，只在参数为 `True` 时放行精确配置路径；
4. `management_app()` 只接受环境变量精确值 `1`，其他值全部保持关闭；
5. 不放行 disable、restore 或任何其他 POST；密码登录原有独立门禁保持不变。

## 4. 默认与正式运行边界

- 默认开关关闭；当前正式进程不重启，因此本轮代码不会改变运行中行为；
- 当前业务库没有专用身份文件，readiness probe 会在数据库连接前失败关闭；
- 即使误设 HTTP 开关，缺少合格专用数据库身份仍不能保存配置；
- 即使数据库身份就绪，未显式设置 HTTP 开关也不能提交配置；
- 本轮不在当前业务库创建角色/策略，不生成身份文件，不执行 POST。

## 5. 验证标准

1. 四项材料齐备但保存通道缺失时，预览必须 `needs_input`；
2. 五项均通过时，预览才 `reviewable`；
3. readiness probe 真实保持只读，不把连接切为读写；
4. 默认 HTTP 外壳继续拒绝配置 POST；
5. 精确布尔开关只放行 configure，其他 POST 全部 405；
6. 非布尔构造参数和非 `1` 环境值不能意外开门；
7. 专项、生命周期 API、只读外壳和相邻 Route worker 回归通过。

## 6. 非目标

- 不代表用户已确认配置；
- 不代表当前库已允许写入；
- 不启动 Host、worker、Provider；
- 不改变预算、审批、能力绑定或外部效果门禁；
- 不把页面可见、测试 GREEN 或 HTTP 健康计为真实经营首链验收。
