# 后台处理配置命令 PostgreSQL 隔离验证方案 r2

时间：2026-10-31（Asia/Shanghai）

## 目标

在全新、一次性、仅绑定本机回环地址的 PostgreSQL 16 实例中，验证 r1 代码所要求的真实数据库角色、表权限、强制 RLS、硬租户策略和连接切换行为。验证对象不是当前业务库，不迁移、不复制任何现有数据。

## 资源边界

- 容器名：`aos-route-worker-lifecycle-pg-r2`
- 监听：仅 `127.0.0.1:55439`
- 存储：容器一次性文件系统，不挂载现有卷
- 数据：只创建一张最小形状的 `bundle_installation_command` 测试表
- 角色：测试 owner、`aos_runtime`、`aos_app`、专用登录；均为本实例内新建
- 禁止连接当前业务库、权威卷、正式 API 数据库或其他测试容器

## 验证步骤

1. 确认同名容器不存在，使用本机已有 PostgreSQL 16 镜像启动一次性实例；
2. 创建最小表、专用登录及硬编码 `org-org/dev-project` 的命名 RLS 策略；
3. 只授予 schema `USAGE` 和目标表 `SELECT, INSERT`；
4. 生成权限 `0600` 的临时身份文件，只供本轮测试进程读取；
5. 调用产品连接函数，验证真实 catalog 检查通过且验证后能在事务内：
   - 写入 `org-org/dev-project` 回执；
   - 读取该回执；
   - 拒绝写入其他租户；
   - 拒绝更新和删除；
6. 注入一个额外权限，证明产品连接函数在进入业务事务前拒绝，再撤销并复验；
7. 保存不含密码的结果证据；停止并删除一次性容器和临时身份文件。

## 成功标准

- 产品连接校验器在真实 PostgreSQL 16 上通过最小权限身份；
- 硬租户正向写入成功，跨租户写入被 RLS 拒绝；
- UPDATE/DELETE 被权限拒绝；
- 权限过宽时连接校验器拒绝；
- 清理后容器和临时凭据均不存在；
- 当前业务 API/Web PID、配置 POST 405 和受保护配置文件不存在的边界不变。

## 停止规则

若端口被占用、同名资源已存在、镜像缺失、任何命令目标无法确认，立即只读对账并停止该隔离验证；绝不改用当前业务库补跑。
