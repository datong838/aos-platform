# 别再堆“聊天机器人”：电商多智能体真正需要的是经营闭环

很多多智能体项目的第一张架构图都很热闹：内容 Agent、客服 Agent、导购 Agent、数据 Agent，各自连着一个大模型。演示时每个角色都能对话，进入真实经营后却很快暴露问题：谁决定今天做什么？谁承担预算和风险？任务完成后，如何证明它真的改善了经营？

问题不在 Agent 数量，而在系统缺少闭环。一个可落地的电商智能系统，更像一套“数字经营组织”，而不是一群并排摆放的聊天机器人。

## 从角色清单转向经营循环

最小经营循环可以抽象为：

```text
经营目标与护栏
  → 数据就绪检查
  → 内外部机会研究
  → 生成方案草案
  → 人工批准指定版本
  → 拆解任务 DAG
  → 多角色执行与交接
  → 观察业务结果
  → 归因与复盘
  → 形成经验候选
```

其中，“数据参谋”适合作为总控角色：它观察全局、提出方案、拆解任务、追踪执行、组织复盘。内容、导购、客服、客户运营和活动策划则是专业执行角色。人类经营负责人仍然拥有目标、预算、风险边界和最终批准权。

这个组织模型解决了三个常见问题。

第一，局部最优。内容 Agent 可能只追求曝光，导购 Agent 只追求转化，活动 Agent 只追求成交额。如果没有统一护栏，它们可能以更低毛利、更高退款率和更差客户体验换取表面增长。

第二，责任不清。一个角色产出的内容被另一个角色使用后发生问题，必须能追到来源方案、任务版本、输入证据和批准记录。

第三，无法学习。如果系统只记录“任务已完成”，就无法区分真正有效、无效、有害、尚无结论和根本未执行。

## 目标不是单一成交额

经营目标应该是一棵指标树，而不是一个数字。至少同时观察：

- 获客：有效互动、线索质量、获客成本；
- 成交：咨询转化、推荐接受、客单与成交周期；
- 客户：复购、流失、退订与长期价值；
- 体验：响应、解决、退款、投诉与履约；
- 经营质量：毛利、库存、优惠成本和渠道投入产出；
- 合规：内容风险、越界承诺、隐私与高风险动作拦截。

每个目标都要有停止条件。例如退款率越界就暂停扩大投放，库存不足就降低获客节奏，外部证据过期就禁止据此触达客户。护栏不是事后报表，而是方案的一部分。

## 用任务 DAG 代替“Agent 互相聊天”

自由对话很难表达依赖、验收和失败。更可靠的做法是把批准后的方案拆成任务图。每个任务至少包含负责人、输入引用、依赖、允许的数据域和工具、预算、风险等级、交付物、验收指标、观察窗口与停止条件。

例如一个新客增长任务可以是：

```text
机会研究
  → 内容草稿与合规审核
  → 人工确认发布
  → 线索识别
  → 需求诊断与商品推荐
  → 售后反馈
  → 效果归因
```

后置任务只能消费已交付且通过验收的前置产物。任一环节数据缺失、权限不足或适配器不可用，都应该进入 `BLOCKED`，而不是用模拟结果补齐。

## “完成”不等于“有效”

一次活动按时上线，只能说明交付完成。复盘至少要给出五类结论：有效、无效、有害、证据不足、未实际执行。

归因优先使用 A/B、分组、分批或前后对照，并记录价格、库存、节日、平台流量等干扰因素。没有对照或样本不足时，只能说“存在相关性”，不能把自然增长全部归功于 Agent。

## 最小可用里程碑

首个版本不必一次实现所有角色。更合理的验收是：

1. 基于真实内部数据和可追溯外部证据生成一份方案草案；
2. 人工批准一个不可变的方案版本；
3. 向至少三个专业角色分派有依赖的任务；
4. 产物、交接和状态全程可追踪；
5. 执行后形成复盘，证据不足时诚实给出“无结论”；
6. 只生成经验候选，未经治理不进入长期记忆。

多智能体系统的价值，不是让更多角色同时说话，而是把经营判断、人工责任、专业协作和效果验证连成一条不会断的链。
