# 复购 Agent 如何安全协作：同意状态、频控与最小客户上下文

复购场景不是一个定时生成任务，而是一组必须由确定性策略保护的状态转换。模型可以识别机会、生成内容和解释推荐，却不能自行修改同意状态、降低频率限制或扩大数据用途。

一个最小的触达决策可以表示为：

```text
机会候选
  -> 用途授权检查
  -> 同意状态检查
  -> 频控与静默期检查
  -> 服务风险检查
  -> 商品事实核验
  -> 触达草案或阻断状态
```

只有所有前置条件在执行时仍然有效，触达草案才有资格进入人工确认。下面用合成场景拆解数据参谋、私域管家及其他 Agent 的职责边界。

## 机会识别输出条件，不输出名单

在完全虚构的场景中，数据参谋从聚合经营数据中发现某类客户可能进入复购窗口。它不会立即导出客户名单，而是先验证：

- 购买和履约事实是否完整；
- 商品消耗周期是否只是经验假设；
- 客户是否仍然同意在目标渠道被联系；
- 近期触达、投诉、退订和售后状态是否允许继续；
- 当前库存、价格和替代商品是否有效。

最终输出应是一组可解释的机会条件，而不是“高价值客户”标签。

```yaml
opportunity: "可能进入复购窗口"
supporting_facts:
  - "已完成订单引用"
  - "可解释的时间条件"
required_checks:
  - consent
  - frequency_cap
  - service_risk
  - inventory_freshness
```

任何前置条件不满足，都不能进入自动触达队列。

## 同意状态与用途必须显式建模

数据参谋回答“哪里可能存在经营机会”，私域管家回答“能否联系、何时联系、通过什么渠道联系”。

它使用的最小客户上下文可以包含生命周期阶段、授权渠道、最近互动时间、相关商品引用和服务风险，但不应向其他数字同事扩散电话、地址、完整聊天或无关订单。

一次触达计划至少包含：

- 联系目的和允许用途；
- 目标渠道及同意状态；
- 最早、最晚触达时间；
- 频率上限和静默期；
- 退订、拒绝和人工接管规则；
- 需要内容官和导购顾问提供的产物。

同意状态不能只用一个布尔值表达。至少应区分渠道、用途、来源、生效时间和撤回时间，并由确定性服务在任务创建与动作执行两个时点重复检查。

```yaml
channel: "授权渠道"
purpose: "允许用途"
status: "active | withdrawn | unknown"
effective_at: "生效时间"
checked_at: "最近核验时间"
```

私域管家不是“客户越多越好”的增长工具。它首先是关系治理角色：已经拒绝、退订或处于投诉处理中的客户，应从任务中排除。

## 任务 DAG 保持角色职责分离

复购内容不能直接复制首次获客文案。内容官根据人群阶段和沟通目的生成解释型、提醒型或服务型草稿，并核验其中的商品事实与渠道约束。

导购顾问则判断“推荐什么”：原商品是否仍适合，是否存在更合适的规格、替代项或搭配，以及当前库存和价格能否支持建议。

```text
数据参谋：识别复购机会条件
  -> 私域管家：筛选同意状态并安排节奏
  -> 内容官：生成分阶段沟通草稿
  -> 导购顾问：生成商品建议与替代项
  -> 人工确认触达
  -> 客服专员：承接问题与售后风险
```

内容官不能决定联系谁；导购顾问不能决定何时打扰客户；私域管家也不能修改商品事实。角色边界越清楚，系统越不容易为了局部转化破坏长期关系。

## 执行结果必须进入状态机

消息成功送达只是渠道状态，不是经营结果。系统需要区分：客户未响应、明确拒绝、请求更多信息、接受推荐、完成购买、退订或产生投诉。

这些结果以最小、结构化方式回流：

```yaml
contact_outcome: "requested_more_information"
recommendation_outcome: "pending"
relationship_signal: "neutral"
next_contact_allowed_at: "重新评估时间"
```

数据参谋随后观察复购、毛利、退订、投诉和服务负担。即使短期成交增加，只要退订或投诉明显恶化，这次策略也不能被判为成功。

## 频控、退出和未知态必须由服务端处理

模型可以建议触达时机，但不能自行降低频控、忽略退订或改变客户同意状态。这些边界应由确定性策略执行。

系统至少要测试：

- 同一客户被多个任务同时选中；
- 客户在计划批准后撤回同意；
- 渠道发送超时，结果处于未知状态；
- 推荐商品在发送前缺货或变价；
- 客户进入投诉或售后升级流程；
- 触达成功但长期关系指标恶化。

任何未知状态都不能通过重试无限发送。系统应先对账，再决定恢复、取消或转人工。

## 安全协作的目标是边界稳定

数据参谋和私域管家的协作，解决了两个不同问题：前者判断经营机会是否存在，后者保护客户关系是否允许被使用。内容官、导购顾问和客服专员再分别补充沟通、商品与体验能力。

客户回来，不应是因为系统更擅长打扰，而应是因为它在合适时间提供了真实、相关且可退出的帮助。
