# Agent 记忆如何受控进化：四层记忆、经验晋升与回归评测

Agent 的任务历史不能直接写入长期记忆。一次结果可能依赖临时流量、库存、策略版本或人工介入；如果系统抹掉适用条件，只保留“曾经有效”，偶然结果就会被升级成未来任务的默认规则。

可靠的记忆系统需要一条受治理的晋升流水线：

```text
工作记忆
  -> 情景经验候选
  -> 脱敏、去重与冲突检测
  -> 跨案例评估
  -> 回归测试与人工批准
  -> 版本化语义或程序记忆
  -> 监测、过期与撤销
```

数字团队真正的进化，不是记住更多对话，而是能区分：什么只属于当前任务，什么是一段待验证的经验，什么是稳定事实，什么才有资格升级为可复用的方法。

## 一次成功，不等于一条规律

假设数据参谋在某次经营巡检中发现，一个沉默客群对“使用场景讲解”内容的响应明显提升。内容官据此调整表达，私域管家选择合适时间触达，导购顾问补充商品建议，最终任务达到了预期目标。

团队可以记录这次结果，但不能立刻生成一条规则：

> 面向沉默客户时，应优先发送场景型内容。

因为这句话抹掉了决定结果的条件：客户处于什么生命周期、内容针对什么品类、触达频率是多少、同期有没有价格变化、效果观察窗口多长，以及是否出现退款或投诉等副作用。

一次任务结束后，系统首先得到的应是一份“候选经验”，而不是“永久知识”。候选经验至少需要保留五类证据：

- 当时要解决的经营问题；
- 适用的人群、渠道和时间条件；
- 实际执行过的方案版本；
- 主指标与护栏指标的变化；
- 失败、例外和无法解释的因素。

没有适用条件的经验，几乎一定会被错误迁移。

## 四层记忆，解决四种不同问题

要让多个 Agent 稳定协作，可以把记忆分成四层。

### 1. 工作记忆：只服务当前任务

工作记忆保存当前计划、待办、临时分析结果和交接状态。它需要明确的任务边界和过期时间，任务结束后应清理或归档。

它解决的是“我们现在做到哪一步”，不应该被下一次任务无条件继承。否则，一次临时促销约束可能在数周后仍影响正常推荐。

### 2. 情景记忆：保存带上下文的经历

情景记忆记录“在什么条件下做了什么，结果如何”。它更像可检索的案例，而不是必须执行的规则。

当数据参谋再次发现相似机会时，可以召回相关案例供团队参考，同时展示差异：本次客群是否相同、库存状态是否一致、观察周期是否足够。召回的意义是帮助判断，不是替代判断。

### 3. 语义记忆：保存经过确认的稳定事实

语义记忆包括经过授权的商品属性、业务术语、政策边界和指标定义。它必须有来源、版本、生效范围和失效机制。

“某指标如何计算”属于语义事实；“某次活动让指标增长”则属于情景经验。把两者混在一起，会让暂时结果伪装成稳定知识。

### 4. 程序记忆：保存可复用的方法

程序记忆描述团队应该如何完成一类任务，例如先检查数据就绪，再识别异常，随后生成方案并进入审批。

这是风险最高的一层，因为它会改变未来行为。一个方法只有经过多次验证、对照评估、人工审查和回归测试，才能进入程序记忆。即便进入，也需要版本化、可撤销，并持续监测失效信号。

## 经验如何晋升为记忆

从任务结果到长期记忆，中间需要一条治理流水线：

```text
任务结束
  ↓
提取候选经验：条件、动作、结果、护栏
  ↓
脱敏、去重、冲突检测、适用范围标注
  ↓
跨案例比较与反例检索
  ↓
离线评估与全局回归
  ↓
人工或治理流程批准
  ↓
版本化发布、监测、到期或撤销
```

其中最容易被忽略的是反例检索。系统不只要问“哪些案例支持这条经验”，还要主动寻找“在相似条件下，它什么时候失败过”。如果只有正例，所谓经验很可能只是幸存者偏差。

评估也不能只看输出是否流畅。更可靠的指标包括：建议采纳后的目标改善、护栏违规率、错误召回率、人工改写率，以及遇到新场景时是否愿意承认“不适用”。

## 每个数字同事，都应拥有自己的专业记忆

六个数字同事不应该共享一个无限扩张的公共记忆池。

内容官可以积累不同表达方式的适用条件，却不需要看到客服专员处理个案时的完整对话；导购顾问可以使用经过确认的商品知识，却不应继承私域管家的联系人工作清单；活动策划师需要预算和机制规则，但不需要读取所有客户明细。

团队可以共享的是经过治理的公共事实、政策和交接契约，而不是彼此的原始工作记忆。每次读取还应同时检查角色权限、任务目的、数据范围和记忆版本。

这条边界既保护隐私，也防止角色污染：如果内容官长期吸收售后个案，可能为了回避极少数问题而让全部内容变得保守；如果导购顾问读取了不完整的活动草案，可能提前承诺尚未批准的权益。

## 记忆冲突时，系统必须允许“不知道”

长期运行后，记忆一定会出现冲突。旧方法可能在新渠道失效，两条经验可能适用于不同客群，政策也可能已经更新。

成熟的系统不会简单选择“最新一条”或“出现次数最多的一条”，而是比较来源可信度、生效范围、版本关系和当前任务条件。无法消解时，应降低置信度、暂停自动应用，并把冲突提交给负责人。

同样，记忆必须能过期。商品、渠道和客户偏好都会变化；没有失效日期和撤销路径的知识库，只会越来越自信地使用过时结论。

## 越做越聪明，不是越来越敢做

数字团队的学习能力，最终应该体现在更少的无效建议、更清晰的适用边界、更稳定的护栏表现，以及更准确的人工升级时机上。

治理后的记忆能让数据参谋更快找到相似案例，让内容官少走重复弯路，也让活动策划师在模拟方案时主动看见曾经的副作用。但记忆只提供证据和方法，不能自动扩大行动权限。
