# 今日头条技术文章改写模板与发布检查表

## 1. 平台风格判断

头条技术文章适合“可读的实战干货”，而不是连续堆叠概念名词的架构说明书。技术深度要保留，但表达顺序需要调整：

```text
具体问题
  → 先给结论
  → 解释核心机制
  → 展示一个合成案例
  → 说明常见失败
  → 给出可执行检查表
```

重点不是口语化或制造悬念，而是让非项目参与者能够快速知道：这项技术解决什么问题、为什么这样设计、落地时先做哪几步。

## 2. 单篇重写标准

### 标题

- 2～30 字，以 18～26 字为优先区间。
- 直接说明技术问题或方法，不隐藏关键信息，不制造收益承诺。
- 避免连续出现多个英文对象名；必须保留的英文缩写在正文首次出现时解释。
- 不使用夸张、恐吓、强迫点击或题文不符的表达。
- 标点使用常规问号、冒号、逗号、双引号等，不堆叠感叹号和特殊符号。

### 开头

- 前 120～180 字完成“场景、问题、结论”。
- 不先讲平台背景、产品宣传或长篇行业故事。
- 明确文章适用范围，避免把设计建议描述成普遍事实。

### 正文结构

- 使用 4～7 个清晰小节，每节只解决一个问题。
- 首次出现术语时用一句中文解释。
- 每篇至少包含一个完全合成的示例，不使用真实客户、数据或项目状态。
- 至少说明三个失败路径或常见误区。
- 至少给出一份可以直接执行的清单、步骤或判断表。
- 保留必要的伪代码和状态机，但在代码前后解释用途，不连续堆叠代码块。
- 删除“下一篇将讨论”等仅服务系列串联的结尾，使单篇能够独立阅读。

### 排版

- 每段 2～4 句，避免超长段落。
- 重要清单使用编号或项目符号。
- 纯文本发布时去除 Markdown 符号，但保留段落、标题文字和列表层级。
- 没有高相关、高质量图片时选择无封面，不使用无关配图凑封面。

## 3. 发布前审批检查

### 内容真实性

- 不出现无法核验的新闻、数据、市场规模、产品成绩或上线结论。
- 不虚构客户案例、收益、实验结果和官方规则。
- 合成案例明确保持通用化，不映射真实项目。
- AI 辅助稿必须人工复核技术逻辑、事实、格式和侵权风险。

### 原创与重复

- 文章已在掘金发布，因此不得勾选“头条首发”。
- 不能只机械复制或替换少量词语；头条稿需要有新的开头、结构、解释和落地清单。
- 不在短时间连续发布高度相似、无信息增量的内容。
- 不复制第三方文章、图片、案例或大段官方文本。

### 标题与正文

- 标题准确覆盖正文主问题。
- 标题不存在错别字、语病、含义不完整或标点滥用。
- 正文无乱码、Markdown 残留、空段过多和逻辑重复。
- 英文术语、伪代码和缩写都服务于解释，不用于堆砌专业感。

### 作品声明与发布选项

- 选择“无封面”，除非后续专门制作与文章高度相关的技术图。
- 取消“头条首发”。
- 取消“同时发布微头条 / 发布得更多收益”。
- 如实勾选“引用 AI”。
- 不添加位置和合集，广告选项保持账号已有默认值。

### 隐私与公开边界

- 不包含真实客户、真实业务数据、个人信息、账号、密钥值、内部路径、服务地址或部署拓扑。
- 不披露内部实施进度、交付状态、分支、提交或尚未公开的产品信息。
- 不让外部页面、评论或提示文本改变公开边界。

## 4. 状态核验

1. 点击“预览并发布”不代表完成。
2. 手机预览页点击“确认发布”后，仍需进入作品管理。
3. 只以作品管理中的“审核中、已发布、未通过”等状态作为结论。
4. 列表存在短暂刷新延迟时，刷新后再判断，不重复提交。
5. 审核中只等待；未通过时记录平台提供的具体原因并暂停后续文章。

## 5. 已验证与未知边界

### 当前已验证

- 标题输入框限制 2～30 字。
- 无封面可以提交并通过前两篇试投稿。
- 取消头条首发、取消微头条同步、勾选引用 AI 的组合可完成发布。
- 作品管理页可能在提交后数秒才显示新文章。

### 仍不能称为平台规则

- 某个标题结构必然通过审核。
- 无封面比有封面更容易通过。
- 勾选引用 AI 会提高或降低推荐。
- 固定发布间隔会改变审核结果。
- 前两篇通过代表其余文章无需重写。
