# Agent记忆怎么设计：四层模型与治理清单

给 Agent 接上向量库，再把对话、网页和任务结果全部存进去，看起来就有了“长期记忆”。但系统运行一段时间后，经常出现三个问题：旧规则反复被召回、一次偶然成功被当成通用经验、不同用户的数据互相串用。

问题不在向量检索本身，而在于把“能搜到的文本”误当成“可以相信的记忆”。更稳妥的做法，是先把记忆分层，再为每一层设置进入、使用、过期和撤回规则。

## 先把记忆分成四层

第一层是工作记忆。它保存当前任务的输入、中间结果和临时判断，任务结束后就应该过期。工作记忆的目标是保证当前流程连贯，而不是形成长期知识。

第二层是经历记忆。它记录一次任务发生了什么，例如采用了什么方案、结果如何、哪些条件影响了结果。这类记忆只能说明“当时发生过”，不能直接推导“以后都应该这样做”。

第三层是语义记忆。它保存经过多次证据支持的稳定事实，例如业务术语、产品约束和公开规则。即使是稳定事实，也需要来源、版本和复核时间。

第四层是流程记忆。它描述 Agent 应该怎样做事，例如“执行建议前先核对库存和权限”。流程记忆会直接改变系统行为，因此需要最严格的评测和人工批准。

可以用一句话区分它们：

```text
工作记忆管当前任务
经历记忆管发生过什么
语义记忆管什么是事实
流程记忆管以后怎样行动
```

## 一个合成案例：一次成功不能直接变成规则

假设某个合成测试中，Agent 在特定时段采用方案 A，任务完成率有所提高。如果系统直接把“以后优先采用方案 A”写入长期记忆，就忽略了当时的数据范围、适用对象、时间窗口和其他变量。

正确做法是先生成一条经历记忆：记录当时的条件、使用的方案版本、结果和证据。只有当多个独立样本都支持相同结论，并且反例、风险与适用边界经过复核后，才允许形成流程记忆候选。

这就是记忆治理最重要的原则：一次成功产生候选，不产生永久规则。

## 记忆进入系统前要过六道门

一条候选记忆可以按以下顺序处理：

1. 来源检查：能否追溯到任务、数据版本和结果。
2. 隐私检查：是否包含个人信息、敏感字段或不该共享的上下文。
3. 适用范围检查：它属于哪个用户、项目、业务域和用途。
4. 质量评测：结论是否有证据，是否存在反例或明显偏差。
5. 人工审批：高影响的共享记忆和流程记忆不能由创建者独自批准。
6. 生命周期设置：明确生效时间、复核时间、过期时间和撤回方式。

只有通过这些检查，候选才能进入激活状态。否则应该保留为草稿、进入隔离区，或者直接拒绝。

## 记忆正文不要只保存一段话

自由文本方便生成，却不利于判断适用边界。一条可治理的记忆至少应包含：

```text
结论：被验证的事实或方法
适用条件：什么时候可以使用
禁用条件：哪些场景不能使用
证据：来自哪些任务和结果
置信度：当前证据支持程度
版本：本次修订编号
复核时间：什么时候重新验证
```

向量索引只是检索副本。权威记忆需要保存在支持版本、审批和撤回的存储中。索引可以重新生成，但审批记录和版本历史不能只存在索引元数据里。

## 检索顺序不能只看相似度

很多系统先做向量检索，再过滤权限。这会让不该访问的内容先进入候选集，也容易把过期但相似的片段排在前面。

更稳妥的检索顺序是：

1. 检查用户身份和本次用途。
2. 限定用户、项目和数据范围。
3. 排除未批准、已过期和被撤回的版本。
4. 再执行关键词或向量召回。
5. 根据证据新鲜度、冲突和适用条件重新排序。
6. 按最小披露原则装配给 Agent 的上下文。

“最相似”只能决定候选相关性，不能替代权限、时效和可信度。

## 三类常见失败

### 失败一：旧规则仍在影响新任务

业务规则已经更新，旧片段却仍在向量索引中被召回。解决方法不是只修改正文，而是禁用旧版本、生成新版本，并清理或重建派生索引。

### 失败二：不同范围的数据互相串用

如果记忆只带文本、不带用户、项目和用途边界，检索器可能把一个范围内的经验提供给另一个范围。范围过滤必须发生在召回之前。

### 失败三：外部内容污染流程记忆

网页、评论和用户输入只能成为证据候选，不能直接改写 Agent 的行为规则。异常高频建议、单一来源自证、循环引用和操控性文本，都应进入隔离区。

## 怎么判断记忆真的有用

“库里存了多少文本”和“向量命中了多少次”都不是能力指标。上线记忆前后，至少要比较：

- 任务完成率和事实准确率是否提高；
- 人工修改率是否下降；
- 过期或错误记忆被复用的次数；
- 延迟和上下文成本是否可接受；
- 权限、隐私和安全违规是否增加。

只有质量改善且安全没有退化，才应该逐步扩大召回范围。

## 一份可以直接使用的落地清单

准备为 Agent 增加记忆能力时，可以逐项检查：

1. 是否区分工作、经历、语义和流程四类记忆。
2. 每条记忆是否能追溯到来源和版本。
3. 是否声明适用条件、禁用条件和复核时间。
4. 高影响记忆是否经过独立审批。
5. 检索是否先过滤范围、权限和状态，再计算相似度。
6. 旧版本能否立即禁用并从索引中清理。
7. 是否记录每次运行实际使用了哪些记忆版本。
8. 是否用任务质量和安全指标验证记忆价值。

Agent 记忆的核心不是“记得越多越好”，而是每一条经验都知道从哪里来、什么时候适用、什么时候失效，以及出了问题怎样撤回。做到这些，向量库才是检索工具，记忆才真正成为可治理的能力。
