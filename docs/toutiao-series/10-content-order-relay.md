# 一条内容怎样变成订单：三类Agent的契约接力

多 Agent 链路最容易犯的错误，是用自然语言隐式传递状态：内容角色说“有人感兴趣”，导购角色就开始推荐，订单结果又被直接归因给最早发布的内容。中间没有用途授权、事实版本和状态引用，任何一步发生变化，整条归因链都会失真。可靠的内容到订单链路，需要内容、导购和客服围绕一组明确契约接力，而不是共享一段不断增长的对话。

## 第一棒：内容版本必须绑定事实包

数据参谋发现某类公开问题正在增加，希望内容角色制作解释型内容。任务不能只是“追热点、提高转化”，而应提供受控简报：

```text
目标：解释常见选择难题并引导理性咨询
受众：匿名化人群描述
事实：已核验商品事实版本
渠道：篇幅、格式和发布约束
禁区：无法证明的效果或稀缺承诺
信号：有效咨询和低误解率
```

内容角色完成选题、事实核验、渠道适配和合规检查。可交付物不是一段孤立文案，而是带来源引用的内容版本：关键表述能追到商品事实，无法证明的效果、价格和稀缺性不能进入正文。

库存过期、商品属性冲突或渠道规则未核验时，任务停在草稿阶段。模型写得再流畅，也不能用语言能力填补事实缺口。

## 第二棒：互动不能直接变成销售线索

阅读、点赞和普通评论只能说明发生了互动，不代表用户请求推荐，更不代表同意后续触达。

系统应先执行意图、用途和同意状态检查，再生成最小线索信号：来源内容版本、关注主题、相关商品引用、明确表达的意图、同意状态、置信等级和失效时间。

```text
公开互动
  → 意图识别
  → 同意与用途检查
  → 最小线索信号
  → 导购任务队列
```

“看过内容”“询问价格”和“请求推荐”是不同意图。低置信度信号应等待澄清，不能为了增加线索数量，把所有互动者都变成销售对象。

下游也不需要完整评论、账号资料和历史行为。线索对象只携带完成咨询响应所需的最小字段，并在过期后停止使用。

## 第三棒：推荐版本必须引用用户约束

导购角色接到线索后，先确认使用场景、限制条件、预算范围和不适用情况。信息足够后，才能检索和比较商品。

可靠的推荐草稿至少包含：

• 候选商品及事实版本。
• 推荐理由与用户约束的对应关系。
• 库存、价格和可售状态的核验时间。
• 替代选项及各自权衡。
• 尚未确认的信息和风险提示。

候选不足、库存过期、价格冲突或需求未澄清时，正确输出是“需要更多信息”，而不是强行生成商品链接。导购只能生成可审查的建议包，真实发送、优惠和承诺仍需要相应权限与批准。

## 第四棒：客服反馈要反向校验内容和推荐

订单产生后，链路没有结束。物流问题、使用疑问、退换请求和投诉，往往比支付结果更能说明前面的内容和推荐是否可靠。

客服角色只读取最小订单引用、当前履约事实、适用政策和问题摘要，负责分类、事实装配、回复草稿和人工升级，不能自行承诺系统中不存在的赔付或时效。

处理完成后，它生成脱敏服务反馈：问题类型、严重程度、关联内容版本、关联推荐版本、处理状态和聚合标签。内容角色不需要客户身份和完整对话，聚合后的误解点已经足够触发内容复核。

## 一个合成案例：从选择指南到服务反馈

假设一个完全合成的场景：内容角色发布了选择指南 C7，其中所有商品描述都绑定事实版本。某位用户明确留言请求比较两个方案，系统在用途和同意状态检查后生成线索 L3。

导购角色发现用户尚未说明使用限制，因此先提出澄清问题。信息补充后，它生成推荐版本 R5，列出两个候选、适用条件和库存核验时间。用户最终选择其中一个方案，订单 O2 记录了 R5 的引用。

售后阶段出现“某项描述容易误解”的反馈。客服角色生成服务案例 S4，并关联 C7 与 R5。数据参谋据此检查：问题来自内容表达、推荐理由，还是履约事实变化。

这条链允许团队回答订单与哪版内容、哪条线索和哪版推荐有关，也允许问题沿相同引用反向返回，而不需要让三个角色共享全部上下文。

## 三类常见失败

第一类是把公开互动直接当成购买意图。系统忽略用途与同意状态，既容易误触达，也会制造虚假的线索转化率。

第二类是推荐不引用事实版本。价格、库存或属性变化后，团队无法判断当时建议依据的究竟是哪一版信息。

第三类是只把支付记为成功。退款、投诉和描述误解没有回流，内容与推荐就会持续重复同一种错误。

还要避免把时间接近当作因果。内容发布后出现订单，只能说明相关；缺少线索、咨询、推荐和观察窗口引用时，不能把成交全部归因给内容或 AI。

## 一份可执行的接力检查清单

1. 内容是否绑定已核验的商品事实和渠道约束。
2. 无法证明的效果、价格和稀缺表述是否被阻断。
3. 互动是否经过意图、用途和同意状态检查。
4. 线索是否只携带最小字段并设置失效时间。
5. 推荐是否引用用户约束、商品版本和核验时间。
6. 信息不足时是否允许输出“需要澄清”。
7. 真实发送、优惠和承诺是否有独立权限与批准。
8. 订单是否保存关联推荐版本，而不是只记最终商品。
9. 服务反馈是否脱敏并反向关联内容和推荐版本。
10. 归因是否区分相关性、证据不足和未实际执行。

内容、导购和客服真正形成团队，不是因为它们都会生成文字，而是因为每一棒都交付一个有用途、版本、状态和最小字段的对象，数据参谋才能沿这条引用链还原结果并修正下一轮行动。
