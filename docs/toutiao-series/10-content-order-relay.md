# 内容信号如何归因订单：多Agent契约与状态

多 Agent 链路最容易出现的工程错误，是用自然语言隐式传递状态：内容 Agent 说“有人感兴趣”，导购 Agent 就开始推荐，支付结果随后又被直接归因给最早的内容。中间缺少用途授权、事实版本和状态引用，任何一步发生变化，整条归因链都会失真。

可靠实现需要先定义五类不可混用的对象：

```text
内容版本
  -> 线索信号
  -> 咨询任务
  -> 推荐版本
  -> 订单与服务结果
```

每个对象只表达一个阶段的事实，并通过稳定引用连接前后版本。本文使用合成场景说明内容、导购与客服三个 Agent 如何围绕这条契约链协作。

## 内容版本必须绑定事实包

数据参谋发现某类公开问题正在增加，希望内容官制作一份解释型内容。它不能只下达“追热点、提高转化”的模糊任务，而应提供一份受控内容简报：

```yaml
objective: "解释常见选择难题，并引导理性咨询"
audience: "匿名化人群描述"
product_fact_refs:
  - "已核验商品事实版本"
channel_constraints:
  - "篇幅与格式要求"
forbidden_claims:
  - "无法证明的效果承诺"
success_signals:
  - "有效咨询"
  - "低误解率"
```

内容官随后完成选题、事实核验、渠道适配和合规检查。真正可交付的不是一段孤立文案，而是一组带来源的内容草稿：每个关键表述能追到商品事实，无法证明的功效、价格和稀缺性不得进入正文。

如果库存数据过期、商品属性冲突或渠道规则没有核验，任务应该停在草稿阶段。模型写得再流畅，也不能用语言能力填补事实缺口。

## 互动信号要经过用途与状态检查

内容发布后的点赞和阅读只是互动，不是客户意图。系统需要把公开互动转换成最小化的线索信号，而不是把完整评论、账号资料和历史行为全部交给下游。

一条可交接的线索可以只包含：来源内容版本、关注主题、相关商品引用、明确表达的意图、是否同意继续沟通、置信等级和过期时间。它不代表成交概率，也不授权下游执行触达。

```yaml
content_ref: "内容版本"
intent: "需要进一步确认的意图"
purpose: "咨询响应"
consent_state: "允许或待确认"
confidence: "置信等级"
expires_at: "信号失效时间"
```

```text
公开互动
  -> 意图识别
  -> 同意与用途检查
  -> 最小线索信号
  -> 导购任务队列
```

“看过内容”“问了价格”和“请求推荐”代表不同意图。低置信度信号应等待进一步澄清，不能为了增加线索数量，把所有互动者都变成销售对象。

## 推荐版本必须引用咨询约束

导购接到线索后，先确认场景、约束、预算范围和不适用条件。只有这些信息足够，才进入商品检索与比较。

一个可靠的推荐草稿至少包含：

- 候选商品及其事实版本；
- 推荐理由和客户约束的对应关系；
- 库存、价格和可售状态的核验时间；
- 替代选项及各自权衡；
- 尚未确认的信息和风险提示。

推荐不能根据敏感属性猜测购买力，也不能制造虚假稀缺。候选不足、库存过期、价格冲突或需求没有澄清时，正确输出是“需要更多信息”，而不是强行生成一个商品链接。

导购生成的是人工可审查的建议包。优惠、承诺和真实发送仍需要相应权限与批准。

## 服务结果是反向校验，不是链路尾注

客户下单之后，经营链并没有结束。物流问题、使用疑问、退换请求和投诉，往往比支付结果更能说明前面的内容和推荐是否可靠。

客服专员读取的是最小订单引用、当前履约事实、适用政策和问题摘要。它负责分类、事实装配、回复草稿和人工升级，但不能自行承诺系统中不存在的赔付与时效。

客服还要把问题转换成脱敏反馈：

```yaml
issue_type: "商品理解偏差"
severity: "普通"
related_content_ref: "内容版本"
related_recommendation_ref: "推荐版本"
resolution_status: "已处理"
feedback_tags:
  - "表达需澄清"
```

这里不需要把客户身份和完整对话传回内容官。聚合后的误解点已经足够触发内容复核。

## 归因必须沿版本引用回放

最终复盘不能只看“内容带来了多少订单”。数据参谋需要同时观察：内容互动是否形成有效咨询、推荐是否被接受、支付是否发生、退款与投诉是否变化，以及观察窗口是否完整。

```text
内容版本
  -> 线索信号
  -> 咨询任务
  -> 推荐版本
  -> 成交或未成交结果
  -> 服务结果
  -> 效果复盘
```

如果只能证明内容与成交发生在相近时间，结论就只能是相关性。缺少对照、样本不足或真实发布未登记时，系统应给出“证据不足”或“未执行”，而不是把所有成交归功于 AI。

## 接力质量由契约决定

这条链真正的价值，不是三个 Agent 都会写文字，而是每次交接都有明确契约：内容官只使用已核验事实，导购只接收经授权的最小线索，客服只读取处理问题所需的订单与政策，数据参谋通过版本引用还原结果。

内容、导购和客服因此不再是三个并排的聊天窗口，而是一支各负其责的数字团队。
