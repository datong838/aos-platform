# 活动策划如何平衡毛利、库存与投诉

当转化下降或库存升高时，最容易生成的 AI 建议是“做一次促销”。模型可以很快给出主题、折扣、文案和排期，但经营活动从来不是一道单变量题。

成交额可能增长，毛利却下降；流量可能放大，库存和履约却承受不了；短期订单可能增加，退款与投诉也可能随后上升。

活动策划师真正需要管理的，不是优惠券，而是经营节奏。

## 数据参谋先判断是否真的需要活动

在一个完全虚构的场景中，数据参谋发现某类商品周转变慢。它首先排除数据延迟、渠道变化、价格异常和履约问题，再形成活动机会草案。

机会草案必须包含基线、假设和反证条件：

```yaml
problem: "特定商品周转放缓"
hypothesis: "目标人群需求仍在，但当前机制吸引力不足"
baseline_refs:
  - "销量与库存快照"
  - "毛利和退款观察"
counter_signals:
  - "履约能力不足"
  - "投诉正在上升"
```

如果真正原因是商品评价恶化或履约延迟，促销只会放大问题。数据参谋此时应建议先修复服务，而不是把活动任务交给下游。

## 活动策划师先模拟护栏，再生成创意

活动策划师接到的是经过批准的机会条件和经营边界。它需要同时考虑人群、商品、库存、预算、毛利、履约和客户体验。

一份可审查的活动方案至少包含：

- 目标人群和排除人群；
- 商品、库存及价格事实版本；
- 活动机制、预算和成本上限；
- 毛利、退款、投诉和履约护栏；
- 内容、导购、私域和客服的子任务；
- 观察窗口、暂停条件和回滚方案。

活动机制只是其中一项。模型给出的“最优折扣”不能直接生效，服务端仍需重新计算价格、预算和毛利边界。

```text
候选机制
  -> 预算校验
  -> 毛利校验
  -> 库存与履约校验
  -> 客户体验校验
  -> 人工批准精确版本
```

## 一场活动是跨角色任务图

方案批准后，活动策划师把它拆成有依赖关系的任务，而不是在群聊里让其他 Agent 自由发挥。

```text
活动方案与护栏冻结
  -> 内容官：生成渠道内容和事实审核包
  -> 私域管家：筛选已授权人群并安排触达节奏
  -> 导购顾问：准备商品比较、搭配和异议处理
  -> 客服专员：准备高频问题、升级路径和服务容量
  -> 人工批准具体发布与触达
  -> 执行观察
  -> 活动复盘
```

内容官不能私自扩大优惠承诺，私域管家不能突破频率上限，导购顾问不能推荐缺货商品，客服专员也不能创造不存在的补偿政策。

每个产物都绑定方案版本。活动预算或商品范围变化后，旧内容、旧推荐和旧批准应重新校验。

## 暂停条件比自动加码更重要

很多自动化系统擅长在效果变好时扩大流量，却没有同等强度的止损机制。活动策划师必须持续观察：

- 可售库存和履约负载；
- 实际毛利和优惠成本；
- 退款、投诉和负面反馈；
- 触达频率、退订和客户疲劳；
- 渠道异常和外部执行未知状态。

任何硬护栏触发后，系统应生成暂停或缩减建议。是否自动执行，取决于动作风险、可逆性和预先批准范围，而不是模型对建议有多自信。

```text
正常 -> 观察
接近护栏 -> 降速建议 + 人工关注
突破护栏 -> 暂停建议 / 受控停止
外部状态未知 -> 禁止重复执行，先对账
```

## 成交增长不等于活动有效

活动复盘需要回答的是“活动带来了多少增量”，而不是“活动期间卖了多少”。

应优先使用分组、分批、时间对照或其他可解释设计，并记录价格、自然流量、季节、渠道资源和库存变化等干扰因素。没有对照时，只能描述相关变化，不能把所有订单记作活动贡献。

复盘至少同时观察成交、毛利、库存、退款、投诉和后续客户质量。短期成交上升但售后恶化，应被标记为有害或需要继续观察，而不是成功案例。

## 活动策划师是节奏控制器

一个成熟的活动策划师，不是最会生成促销点子的 Agent。它更像数字团队的节奏控制器：知道什么时候值得放大，什么时候应该等待，什么时候必须停下来解决基础问题。

数据参谋负责发现机会和归因，活动策划师负责模拟机制、协调资源和守住护栏，其他数字同事在明确任务与权限内完成专业交付。只有这样，活动才从一次营销动作变成可审查、可停止、可复盘的经营实验。

下一篇将从活动之后最容易被忽略的信号开始：一次投诉如何逆向改变内容表达和商品推荐，让数字团队不再沿着错误方向持续放大。
