# 活动不是发优惠券：如何在毛利、库存和投诉间决策

转化下降或库存升高时，AI 最容易生成的建议是“做一次促销”。主题、折扣、文案和排期几秒钟就能给出，但经营活动不是单变量题：成交额可能增长，毛利却下降；流量可能放大，库存和履约却承受不了；短期订单增加，退款和投诉也可能随后上升。活动策划真正管理的不是优惠券，而是经营节奏与风险边界。

## 先判断问题是否真的需要活动

假设一个完全合成的场景：某类商品周转变慢。数据参谋不能直接把“库存高”翻译成“降价促销”，而应先排除数据延迟、渠道变化、价格异常、评价恶化和履约问题。

一份活动机会草案至少包含：问题基线、经营假设、数据快照、可支持的分析范围，以及可能推翻结论的反证条件。

```text
问题：某类商品周转放缓
假设：目标人群仍有需求，但当前机制吸引力不足
基线：销量、库存、毛利、退款和投诉快照
反证：履约不足、评价恶化、投诉正在上升
```

如果真正原因是商品描述误导或履约延迟，促销只会放大问题。此时正确动作是先修复内容或服务，而不是创建活动。

## 先模拟护栏，再讨论创意

活动策划角色接到经过批准的机会条件后，需要同时考虑人群、商品、库存、预算、毛利、履约和体验。

可审查的活动方案至少包含：

• 目标人群和排除人群。
• 商品、库存与价格事实版本。
• 活动机制、预算和成本上限。
• 毛利、退款、投诉和履约护栏。
• 内容、导购、客户运营和客服子任务。
• 观察窗口、暂停条件和回滚方案。

模型给出的折扣建议不能直接生效。服务端仍要根据最新价格、可售库存、优惠成本和毛利边界重新计算。

```text
候选机制
  → 预算校验
  → 毛利校验
  → 库存与履约校验
  → 客户体验校验
  → 人工批准精确版本
```

方案中任何商品、预算或机制变化，都应生成新版本，旧批准不能继续覆盖。

## 活动执行是一张跨角色任务图

方案批准后，活动策划角色把它拆成有依赖的任务，而不是让其他 Agent 在群聊中自由发挥。

```text
冻结活动方案与护栏
  → 内容角色：生成渠道内容与事实审核包
  → 客户运营：筛选已授权人群并安排节奏
  → 导购角色：准备比较、搭配与异议处理
  → 客服角色：准备高频问题和升级路径
  → 人工批准具体发布与触达
  → 执行观察
  → 活动复盘
```

内容角色不能扩大优惠承诺，客户运营不能突破频率限制，导购角色不能推荐缺货商品，客服角色不能创造不存在的补偿政策。每个产物都绑定活动方案版本和事实版本。

## 一个合成案例：活动效果好时也可能需要降速

在这个合成场景中，活动方案 A3 计划小范围测试两种机制。系统先预留预算和库存，人工批准精确内容与对象范围后开始第一批执行。

初期支付转化上升，但可售库存下降速度超过预期，客服等待时间也接近护栏。活动策划角色没有自动扩大流量，而是生成降速建议：暂停第二批人群、保留已承诺订单、缩小内容曝光，并要求重新核对履约容量。

随后退款原因显示，部分用户对活动条件理解不一致。系统把聚合问题反向交给内容和导购角色修订表达，旧内容版本停止继续使用。

这个案例说明，短期转化变好不等于应该加码。活动系统必须有与放大能力同等强度的减速和停止机制。

## 暂停条件必须是运行时状态

活动执行期间持续观察：可售库存、履约负载、实际毛利、优惠成本、退款、投诉、退订、客户疲劳、渠道异常和外部动作未知态。

```text
正常：继续观察
接近护栏：生成降速建议并提醒人工
突破护栏：暂停建议或受控停止
外部状态未知：禁止重复执行，先对账
```

是否允许自动停止，取决于动作风险、可逆性和预先批准范围，而不是模型置信度。高风险或影响用户权益的动作应保留人工确认。

## 三类常见失败

第一类是只看成交额。活动增加订单，却同时降低毛利、推高退款和投诉，仍被记录为成功。

第二类是先生成创意、后补经营边界。内容和触达方案已经扩散，团队才发现库存、预算或履约不支持。

第三类是效果变好就自动加码。系统没有减速和停止状态，一次局部成功被无限放大，最终突破库存与服务容量。

还要避免把活动期间的所有订单都算作活动贡献。缺少分组、分批或其他对照时，只能描述相关变化，不能声称存在确定增量。

## 一份可执行的活动检查清单

1. 是否先排除数据、价格、评价和履约问题。
2. 机会草案是否包含基线、假设和反证条件。
3. 活动方案是否绑定商品、库存、价格与政策版本。
4. 是否同时设置预算、毛利、库存、履约和体验护栏。
5. 人工批准是否绑定精确机制、内容、对象范围和时间窗。
6. 跨角色任务是否有输入、交付物、验收和停止条件。
7. 运行时是否持续读取最新库存、毛利和服务状态。
8. 是否具备降速、暂停、回滚和外部未知态对账路径。
9. 复盘是否区分成交、增量、毛利、退款、投诉和后续质量。
10. 证据不足时是否允许输出“暂时无结论”。

成熟的活动策划角色不是最会生成促销点子的 Agent，而是数字团队的节奏控制器：知道什么时候值得试验，什么时候可以放大，什么时候应当等待，以及什么时候必须先解决基础问题。
