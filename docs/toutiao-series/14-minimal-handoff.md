# 多Agent安全交接：为什么共享越多风险越大

多智能体协作最危险的误区，是把“信息越多，判断越准”当成默认前提。上游将完整对话、客户资料、工具结果和历史记忆全部交给下游，可能同时扩散隐私、过期事实和恶意指令。更可靠的做法，是把每次交接做成一个用途明确、字段最小、权限重验、到期失效的结构化对象。

## 交接的不是聊天记录，而是一份任务契约

设想一个完全虚构的内容咨询场景：内容 Agent 识别到一条选购问题，需要交给导购 Agent 继续处理。

导购真正需要的通常只有来源内容、关注商品、意图摘要、用户主动提供的约束、同意状态和失效时间。它不需要上游系统提示词、完整评论区、平台凭据，更不需要其他用户的资料。

一份最小交接对象可以写成：

source_task: 内容线索识别任务
target_role: 导购顾问
purpose: 响应用户主动提出的选购问题
allowed_fields: 内容引用、商品引用、意图摘要、同意状态
forbidden_fields: 平台凭据、无关对话、其他用户数据
expires_at: 交接失效时间

自然语言可以描述任务目标，但权限不能靠模型从自然语言中猜。来源、接收角色、允许用途、字段白名单和有效期都应由系统明确校验。

## 最小上下文要按用途重新组装

“最小化”不是从一份大对象里随手删掉几个字段，而是服务端根据当前角色和用途重新组装上下文。

• 内容 Agent 需要匿名化人群特征和内容效果，不需要个体身份
• 导购 Agent 需要当前咨询约束和商品事实，不需要完整售后历史
• 客服 Agent 需要受控订单引用、问题摘要和适用政策，不需要营销画像
• 关系运营 Agent 需要同意状态、触达节奏和关系信号，不需要详细地址
• 数据分析 Agent 优先读取聚合结果和产物引用，不读取原始自由文本

同一个用户，在不同任务里对应的可见字段应该不同。职责分离不是把角色名称写进提示词，而是让数据访问范围真正随用途变化。

## 上游有权限，不代表下游自动继承

每次交接至少重新验证六件事：

1. 来源任务已经批准，并且仍然有效
2. 上游产物存在、未撤回、没有过期
3. 接收角色有权为当前用途读取这些字段
4. 来源与目标处在允许协作的组织和项目边界内
5. 敏感等级没有在传递过程中被降低
6. 用户同意状态在交接时仍然有效

任何一项失败，交接都应默认关闭。模型不能用“为了提供更好的服务”作为扩大权限的理由。

## 摘要不会自动降低敏感等级

很多系统会误以为，原始数据经过模型总结后就变得安全。实际上，只要摘要仍能识别个人、推断敏感事实或关联具体订单，它就应该继承输入中的最高敏感等级。

订单引用：受限

咨询摘要：受限

公开商品事实：公开

最终交接对象：受限

只有经过专门的去标识、聚合和重新评估流程，数据才可能进入更宽的共享范围。“改写过”与“已脱敏”不是同一件事。

## 过期、撤回和冲突必须成为正式状态

用户可能在任务执行中撤回同意，商品可能变价，内容可能被删除，订单状态也可能变化。因此交接对象必须携带版本和失效时间，下游开始工作前还要刷新关键引用。

执行过程中一旦发现变化，不应继续使用旧上下文，而应进入明确状态：

BLOCKED：权限或必要条件不满足

NEEDS_REFRESH：关键事实需要重新获取

REVOKED：同意或上游产物已被撤回

这些状态让系统能够安全停止、转人工或重新计算，也让事后审计知道任务为何没有继续。

## 七类失败场景最值得优先测试

安全交接不能只测正常路径，至少要覆盖下面七类负向场景：

• 跨组织或跨项目的任务尝试交接
• 为售后目的收集的数据被用于营销
• 用户撤回同意后，任务仍尝试触达
• 下游请求字段白名单之外的数据
• 上游产物已经过期或被撤回
• 外部内容中的提示词注入进入交接摘要
• 两个并发任务同时修改同一交接状态

常见失败之一，是把权限检查只放在任务开始处，导致长任务使用已经过期的授权。另一个失败是只记录交接成功，不记录拒绝原因，最终无法区分数据缺失、权限不足和事实过期。第三个失败是让所有角色共享同一长期记忆，使临时判断和个体信息跨任务扩散。

## 可直接执行的安全交接清单

准备上线多 Agent 协作前，可以逐项确认：

• 每次交接是否有唯一任务引用和明确接收角色
• 是否写明当前用途，而不是使用“提升体验”等宽泛理由
• 是否由服务端按用途生成字段白名单
• 是否在交接时重新检查权限、同意和组织边界
• 是否让敏感标记随数据向下游传播
• 是否携带来源版本、有效期和撤回状态
• 是否把阻断、刷新、撤回定义成正式状态
• 是否禁止共享系统提示词、凭据和其他用户资料
• 是否记录允许字段、拒绝字段与决策原因
• 是否完成跨域、撤回、过期、注入和并发负向测试

限制上下文不会让 Agent 变笨。它迫使系统明确每个角色为什么需要一项信息、能用多久、可以产生什么结果，以及失败时如何关闭。多智能体协作的质量，不取决于共享窗口有多大，而取决于任务契约、字段边界、权限重验和生命周期是否足够清楚。
