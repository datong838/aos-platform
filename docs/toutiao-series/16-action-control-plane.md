# 多 Agent 动作控制面：风险分级、执行租约与未知态对账

多个 Agent 共享发布、发送或业务写入能力时，不能分别依赖各自的提示词控制风险。即使每个 Agent 单独执行一次，多个并发任务仍可能造成重复动作、预算叠加和状态冲突。

因此，外部动作需要经过统一控制面：

```text
Agent 动作提案
  -> 服务端风险分级
  -> 精确版本审批
  -> 幂等与预算预留
  -> 执行租约
  -> 外部调用
  -> 结果核对或未知态对账
  -> 审计与补偿
```

控制面的目标不是让 Agent 更容易调用工具，而是证明每次动作被授权、没有越界、不会重复，并且在网络超时或部分成功后能够停止、核对和补救。

## 先按后果，而不是按按钮给动作分级

同样是调用工具，风险可能完全不同。可以先把能力分成五级：

| 级别 | 典型能力 | 默认控制方式 |
| --- | --- | --- |
| R0 | 查询公开或已授权数据 | 只读、留痕 |
| R1 | 生成分析、文案或建议 | 仅草稿 |
| R2 | 创建待审核任务、保存草稿 | 明确范围，可撤销 |
| R3 | 发布内容、发送消息、修改普通配置 | 精确审批，限量执行 |
| R4 | 改价、库存、支付、退款等高影响动作 | 双人复核或更严格控制 |

风险级别不应由调用者在请求里自行填写，而应由服务端根据动作类型、影响范围、金额、受众数量和可逆性计算。否则，一个 Agent 只要把“批量触达”标成低风险，就可能绕过真正的控制。

## 审批的不是一句话，而是一个不可偷换的动作版本

“同意这个方案”并不足以授权执行。人在审批时看到的对象，必须和最终执行的对象完全一致。

一份动作提案至少应绑定：

- 对应的经营计划和任务；
- 内容、价格或配置的精确版本；
- 目标渠道、账户和受众范围；
- 允许调用的能力及其边界；
- 预算、频率和有效时间窗；
- 标准化后的参数摘要与校验值。

如果审批后文案被改了一个数字、受众从小范围变成全量，或者价格参数发生变化，原审批都应失效，必须重新提交。

这就是“批准动作版本”，而不是“批准 Agent 自由发挥”。

## 从建议到执行，需要七个状态

一个完整的受控动作可以经过以下状态：

```text
建议
  → 草稿
  → 动作提案
  → 精确审批
  → 受控执行
  → 结果核对
  → 效果复盘
```

每次状态变化都要记录操作者、输入版本、时间和原因。审批人与提案人还可以根据风险进行职责分离：普通草稿由一人确认，高影响动作则要求另一名负责人复核。

这条链路也让“人机协同”变得可审计。出了问题，团队能判断问题来自分析、草稿、审批、执行还是外部系统，而不是只看到一句“Agent 操作失败”。

## 网络超时，不代表动作没有发生

假设客服专员提交了一次权益补偿，连接在返回结果前超时。最危险的做法，是立刻重试。第一次请求可能已经成功，第二次会造成重复补偿。

因此，任何有副作用的动作都需要持久化幂等键：

```text
同一幂等键 + 同一请求 → 返回第一次结果
同一幂等键 + 不同请求 → 拒绝并报告冲突
```

当结果未知时，任务状态应进入“待核对”，先通过查询或对账确认外部事实，再决定是否重试。不能把“没有收到成功响应”等同于“执行失败”。

对于并发执行，还需要租约或栅栏机制，保证同一任务不会被两个执行者同时领取。否则，即使每个执行者内部逻辑都正确，也可能共同制造重复发布和重复触达。

## 自动化必须带着刹车系统

动作能力越强，运行时护栏越重要。至少需要四类刹车：

### 1. 范围护栏

限定账户、渠道、客群、品类和时间窗。Agent 只能在被授权的最小范围内操作。

### 2. 预算与频率护栏

限制金额、优惠成本、触达次数和单位时间内的动作数量。即使单次动作合法，累计影响也不能失控。

### 3. 异常暂停

投诉、退订、退款、库存或价格波动触发阈值时，系统应暂停后续动作并请求人工判断，而不是继续完成原计划。

### 4. 全局停止开关

当外部平台异常、权限配置错误或效果明显偏离预期时，负责人必须能立即停止某类能力、某个账户或全部执行任务。

停止开关本身也要经过权限控制和演练。一个从未验证过的紧急开关，不能算真正的安全能力。

## 改价为什么比发布内容更难

发布错误内容通常可以删除或更正，价格变化却可能立刻引发订单、承诺和合规问题。它不仅要检查目标价格，还要检查毛利下限、活动叠加、渠道一致性、库存状态和生效时段。

因此，改价提案应先在沙箱或模拟环境中计算影响，再以小范围、短时间窗执行。执行后需要读取外部系统的实际价格进行核对，而不是把“请求已发送”当成“价格已生效”。

如果只完成了一部分渠道，系统应冻结后续扩展，生成差异清单，并由预先设计的补偿方案决定回滚、补齐还是维持现状。补偿不是临时想办法，而应在执行前就成为提案的一部分。

## 自动化成熟度，不等于把人全部移出流程

数字团队可以沿四个阶段逐步演进：

1. **仅建议**：Agent 只分析和生成草稿，人完成全部外部操作；
2. **辅助执行**：人批准精确版本，系统代为执行并核对；
3. **监督式自动化**：低风险、重复性动作在严格额度内自动执行，异常立即升级；
4. **有限自治**：只在经过长期验证的场景、明确边界和持续监控下扩大权限。

成熟度的衡量标准，不是自动执行比例越高越好，而是错误影响是否受限、异常是否被及时发现、审批是否真正有效、每次动作能否解释和复盘。

模型置信度也不能替代授权。一个 Agent 即使对建议有百分之九十九的把握，也不能因此获得访问新账户、扩大受众或突破预算的权力。能力来自系统授权，不来自模型自信。

## 数字同事的终点，是可托付而不是全自动

回看整个系列，数据参谋先发现经营问题，再由内容官、私域管家、导购顾问、活动策划师和客服专员协作处理。它们通过最小化交接保护职责边界，通过治理后的记忆积累经验，最后通过受控动作连接真实业务。

这套数字团队的价值，不是让六个 Agent 自由讨论并自动点击所有按钮，而是把经营过程变成一条可解释、可审批、可执行、可核对、可学习的闭环。

真正值得企业托付的人工智能，不只是能提出好答案。它还知道哪些信息不该看，哪些经验不能轻信，哪些动作必须等待批准，以及什么时候应该停下来，把决定交还给人。
