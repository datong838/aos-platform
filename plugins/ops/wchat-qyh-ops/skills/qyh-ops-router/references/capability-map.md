# 能力与任务地图

## 已知观察面

| 观察面 | 最擅长回答 | 不能单独证明 |
|---|---|---|
| 管理后台 | 配置、运营工作流、页面当前状态 | 真实长期效果、完整底层事实 |
| 微信小程序 | 消费者旅程、内容表达、分享触点 | 后台配置、全量转化与利润 |
| Data OS/Connector 上游（不可由 Workshop 调用） | 远程 MySQL/SSH 隧道、Schema、原始表与采样 | 只作为 Dataset lineage 与 DataNeed 的上游责任域 |
| AOS 数据集/本体投影 | P01–P12 受治理对象、关系、指标与跨表分析输入 | 源库实时全貌、尚未映射的长尾表、外部动作结果 |
| 人工说明/访谈 | 商业规则、组织过程、线下成本和意图 | 数据规模、系统一致性 |

## 典型任务组合

- **首次平台/店铺接入**：执行双域全息内省，分别形成页面地图、Schema 地图、语义映射与未知区域；不得把两个运行身份合并。
- **快速找页面**：后台或小程序观察技能。
- **查某张原始表/字段**：不得由工作台执行；形成 DataNeed，引用 source lineage 与所需语义，交给 Data OS。
- **履行已批准 DataNeed**：由 Data OS/FDE 身份调用 `qyh-data-onboarding`，从源发现逐层返回 Dataset/Mapping/Ontology 候选与 Receipt。
- **查经营对象/指标**：只读 P01–P12 数据集、本体对象/关系和质量证据。
- **核验某机制**：后台 + 小程序 + 受治理投影 + 数据语义 + 证据；缺口通过 DataNeed 补证。
- **全店体检**：后台 + 小程序 + AOS 数据集/本体投影 + 社交分销 + 经营诊断 + 证据。
- **形成平台方法**：完成至少一次实例诊断，再比较其他微商城实例；不得直接晋升。

首次全域摸底完成后，后续默认进入增量模式：按稳定地图直达页面、Dataset/Object 或 DataNeed，不重新遍历全部菜单和全部 Schema；只有平台版本变化、覆盖缺口或证据冲突才扩展观察范围。

## 当前稳定认知

栖月汇是“成交 + 内容教育 + 社交传播 + 关系确权 + 收益结算”的私域微商城。当前经营假设是能力供给强于经营供给；必须通过全店体检验证，不能把用户体感直接写成根因。
